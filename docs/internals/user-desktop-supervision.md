# User desktop supervision

The environment binds each User desktop ID to native bootstrap or a
desktop-specific pairing grant. The active socket and its registration
generation own the route. An agent acts as its authenticated thread.
Supervising clients use their current environment-session scopes. The
private child pipe lets the native host verify same-account administration.

Screen permission, the current input lease, and desktop availability
have separate lifetimes. Preparing a thread grant leaves an existing
viewer in control. Availability holds the desktop idle inhibitor.
Ordinary work uses the suspend-only inhibitor. Handoff releases native
held inputs before the next controller acts.

Execution and file access require their own destination grant. An
expired grant leaves accepted jobs running. Authorized people can
inspect or stop them, and registered completion waits can return their
terminal receipt. Each transfer ticket admits one direction for one
archive. Workspace imports recheck the current thread, runtime policy,
and bound directory at publication, including individual merge entries.

A branchless thread can bind to a plain directory. For a branch-backed
thread, Git membership identifies the checkout across branch switches.
Detaching changes the thread binding. Removing its files also needs
exclusive access from live providers, terminals, transfers, and an
attached native host.
